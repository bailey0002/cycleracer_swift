## What this is

`SpeederProto/` is a Swift + RealityKit + Metal prototype of a cyberpunk hover-racer, built from
a ChatGPT brief (`RealityKit_Cyberpunk_Speeder_Claude_Code_Build_Brief.md`) and a Sketchfab
GLB model (converted to `Resources/Speeder.usdz`). It runs on macOS and iPhone from one code base.
Everything except the vehicle is generated procedurally at launch. Status as of 9 Sep 2026:

- Two worlds: **Neon City** (night, frozen as the reference look) and **Sunset Canyon** (daylight).
  `Scene/Theme.swift` defines a world; the HUD `world` picker rebuilds the scene.
- Gameplay: scripted track (`Scene/TrackProgram.swift`) with curves, a fork (tunnel vs skyway),
  a cylindrical conduit, lane obstacles with collisions, altitude, plasma bolts, haptics.
- Input: Backbone / any gamepad (left stick steer+climb, R2 boost, A fire, Menu = settings),
  Mac keyboard, iOS touch (SwiftUI `SpatialEventGesture`, see gotcha below).
- Look system: role-based palettes (road / city / rings / hazards), variant pickers in the HUD,
  `SPEEDER_VARIANT=<name>` presets for capture sweeps.
- Next planned work: a third world, a Tron light-cycle arena. See `SpeederProto/docs/NEXT-THREAD-PROMPT.md`
  and `SpeederProto/docs/lightcycle-research.md`.

## Build, verify, deploy (all from `SpeederProto/`)

- Always `export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` (Xcode 26.6). The Xcode 27
  beta that `xcode-select` points at has no Metal toolchain and fails on the .metal files.
- Project is generated by xcodegen from `project.yml`; run `xcodegen generate` after adding files.
- Mac: `xcodebuild -project SpeederProto.xcodeproj -scheme SpeederProto-macOS -configuration Debug -derivedDataPath build CODE_SIGN_IDENTITY=- CODE_SIGNING_ALLOWED=NO build`
- Visual verification: `screencapture` is blocked here. Run the Mac app with
  `SPEEDER_DEMO=1 SPEEDER_CAPTURE_DIR=<dir> SPEEDER_CAPTURE_TIMES=4,9,17` (fixed 60 Hz step, frames
  are deterministic and pixel-aligned between runs) and Read the PNGs. `SPEEDER_DEMO_BIAS=-0.45`
  takes the tunnel branch; `SPEEDER_VARIANT=canyon` etc. applies a preset. Allow ~30 s per run.
- Phone (Mark's iPhone 12, paired over Wi-Fi, id 1438FC4B-510E-5302-9AAE-0833BC5A856F, team HNBN55RN29):
  the exact build/install/launch command is in `SpeederProto/README.md`. Launch is refused when the
  phone is locked; that is fine, the install still lands. The user expects every meaningful build to
  be pushed to the phone without being asked.
- Simulator (iPhone 16e CC7815D7-8D0B-43FE-A4E1-EA4CBED5E83A): depth reads NaN there, the post pass
  falls back to screen-space fog automatically. The MCP simulator tool's `tap` maps (x, y) to app
  landscape point (y, 390 - x) and its instant tap is too short for a UISwitch; use `touch_path` ~150 ms.

## Gotchas learned the hard way

- `PhysicallyBasedMaterial.EmissiveColor(color:texture:)` adds the colour to the texture; pass `.black`.
- iOS: SwiftUI controls over the ARView never got taps while the ARView handled UIKit touches.
  Fix in place: `arView.isUserInteractionEnabled = false` on iOS, steering via `SpatialEventGesture`.
- The HUD panel must scroll; a long VStack clips silently on a 390 pt tall phone.
- Bloom brightness threshold dominates bloom "intensity"; move both together.
- Fog colour close to scene luminance is invisible; haze must be brighter than what it replaces.
- Multi-file `swiftc` probes need the top-level file named `main.swift`.
- Blender 5.0 (`/Applications/Blender.app`) converts GLB to USDZ; RealityKit cannot load GLB.
